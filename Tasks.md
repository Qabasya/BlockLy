# План реализации

Этапы идут в порядке из раздела «Порядок работ» в `CLAUDE.md`. Следующий этап
начинается, когда у предыдущего выполнен DoD.

**Общий DoD для каждого этапа** (в списках ниже не повторяется):

- Всё работает по `file://` двойным кликом в Chrome/Edge, консоль без ошибок.
- Нет сборки, зависимостей, `type="module"`, `import`/`export`, `fetch`.
- Каждый JS-файл начинается с `window.MKB = window.MKB || {};`, глобальных имён вне `MKB` нет.
- `js/core/*` не обращается к `document`/`window` (кроме namespace).
- CSS использует только переменные из `css/tokens.css`.
- Файлы не больше ~250 строк, имена и комментарии по-русски.
- `tests.html` зелёный целиком (в том числе старые тесты).

Уже есть: `css/tokens.css`, `css/app.css`, `css/admin.css` (сняты с макетов),
`assets/logo.svg`, `mockups/*`, `tools/check-fs-access.html`.
Кода приложения, данных и тестов ещё нет.

## 1. `core/split.js` — дерево из отступов — ✅ готово

**Что делаем**
- Табы → пробелы, пустые строки отбрасываются.
- Удаление комментариев `//` и `#` вне кавычек.
- Шаг отступа — по первому ненулевому отступу в этапе (2 или 4); `depth = отступ / шаг`.
- Хвост — строка по `/^[)\]}\s;,]+$/`, пишется в `closer` открывающего блока, в
  массив блоков не попадает.
- Открывающий блок — под ним строки большей глубины; `bodyCount` = число строк
  тела верхнего уровня; `parentId`.
- `position`, `group`, `free`, `text` без отступа.
- `norm` и `fields` — пока заглушкой, заполняется в этапе 2 (через `fields.js`).

**DoD** — тесты из таблицы `CLAUDE.md`:
- Arduino и Python одинаковой структуры → одно и то же дерево.
- `}` и `});` → хвосты, в блоки не попали.
- `} else {` и `elif x:` → обычные открывающие блоки, без спецветок в коде.
- Цикл в цикле → `depth: 2`, верный `parentId`.
- Шаг 2 и 4 → одинаковый `depth`; табы → верный `depth`.
- `//` и `#` в конце строки удалены, `//` внутри кавычек сохранён.
- Этап МК-3 разбирается в 11 блоков с правильными `bodyCount` и `closer`.

## Решённые вопросы

1. **Одинаковые строки.** В этапе их быть не должно. Если есть — у ученика
   взаимозаменяемы (обе версии засчитываются); при переносе описаний k-е
   вхождение получает описание k-го вхождения.
2. **Описание шага** — описание следующей строки: программа собирается сверху
   вниз, следующая — первая в эталонном порядке непоставленная строка
   (по `norm`), в том числе в свободном фрагменте. Подсказка указывает на тот же блок.

## План новых возможностей

Новые изменения делать отдельными фазами после стабилизации текущего приложения.
Каждая фаза заканчивается своей проверкой, прежде чем начинается следующая.

### 10. Копирование мастер-класса — ✅ реализовано

### 14. Прямая загрузка Arduino через Web Serial — 🧪 основной сценарий подтверждён на плате

Компиляция текущего кода через локальный сервер и загрузка через Web Serial
реализованы. Проверены сборка этапов и обмен с имитацией последовательного
порта, включая обратное чтение прошивки. Пользователь сообщил, что загрузка на
подключённую Arduino Nano ATmega328P с Old Bootloader работает. Отдельно ещё
нужно проверить прерывание загрузки на каждом шаге и целевой сценарий в Edge.

**Поддерживаемая модель** — Arduino Nano, ATmega328P, пункт «Old Bootloader».
Её FQBN: `arduino:avr:nano:cpu=atmega328old`; загрузка использует протокол
`arduino` (вариант STK500v1), скорость 57600 бод, предел скетча 30 720 байт.
Эти параметры заданы в [Arduino AVR Boards](https://github.com/arduino/ArduinoCore-avr/blob/master/boards.txt).
Другие модели и загрузчики пока не входят в объём этой фазы.

Web Serial передаёт байты в порт, но не превращает текст скетча в прошивку.
В `mk3` используется FastLED, а поля допускают разные введённые значения;
готовый HEX для одного варианта не заменяет компиляцию собранного учеником кода.
Загрузчик Nano требует отдельной реализации обмена по STK500v1. Просто выбрать
порт или передать в него текст скетча недостаточно для выполнения задачи.

**14а. Компиляция — реализована**

- Итоговый код текущей сборки после успешной проверки отправляется локальному
  серверу `tools/serve.py`; значения полей попадают в компиляцию.
- Arduino CLI собирает Intel HEX для `arduino:avr:nano:cpu=atmega328old` с
  установленной FastLED. Проверены Arduino AVR Boards 1.8.8, FastLED 3.10.4,
  Arduino CLI 1.4.1 и avr-gcc 7.3.0-atmel3.6.1-arduino7. Сборка работает без
  интернета после установки этих компонентов. Запуск через `file://` остаётся
  для занятий без прямой загрузки. См. [инструкцию](tools/README.md).

**14б. Загрузка HEX через Web Serial и интеграция — реализована, основной сценарий проверен пользователем**

- По нажатию «Загрузить на плату» запрашивается порт через
  `navigator.serial.requestPort()`; открыть его как
  `port.open({ baudRate: 57600 })` и управлять сбросом через
  `port.setSignals({ dataTerminalReady: ... })`. Запрашивать доступ только по
  действию пользователя. Проверять `window.isSecureContext` и
  `navigator.serial` в целевых Chrome/Edge.
- Реализован протокол `arduino`/STK500v1: сброс, синхронизация, чтение
  сигнатуры ATmega328P, запись страниц HEX, обратное чтение и проверку,
  завершение и закрытие порта даже при ошибке. Сверяться с
  [реализацией AVRDUDE](https://github.com/avrdudes/avrdude/blob/main/src/arduino.c)
  и [командами STK500](https://github.com/arduino/ArduinoCore-avr/blob/master/bootloaders/optiboot/stk500.h).
- Интерфейс показывает стадии «компиляция», «подключение», «загрузка», «проверка»
  и прогресс; ошибки доступа, сборки, связи и сверки прошивки отображаются
  ученику. Копирование кода для ручной загрузки сохранено.

**Опорные места** — `js/ui/student.js` (действия и итоговый код),
`js/core/serialize.js` (`buildCode`), `index.html` (кнопка и состояние),
новые модули компиляции и STK500v1.

**Проверка готовности**

- Из итогового кода с FastLED и выбранными значениями полей получается HEX
  для `arduino:avr:nano:cpu=atmega328old` в поддерживаемом режиме запуска.
- После выбора порта на реальной Nano с Old Bootloader программа записывается,
