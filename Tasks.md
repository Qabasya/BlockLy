# План реализации

Этапы идут в порядке из раздела «Порядок работ» в `CLAUDE.md`. Следующий этап
начинается, когда у предыдущего выполнен DoD.

**Общий DoD для каждого этапа** (в списках ниже не повторяется):

- Всё работает по `file://` двойным кликом в Chrome/Edge, консоль без ошибок.
- Нет сборки, зависимостей, `type="module"`, `import`/`export`, `fetch`.
- Каждый JS-файл начинается с `window.MKB = window.MKB || {};`, глобальных имён вне `MKB` нет.
- `js/core/*` не обращается к `document`/`window` (кроме namespace).
- CSS использует только переменные из `css/tokens.css`.
- Файлы не больше ~250 строк, имена и комментарии по-русски.
- `tests.html` зелёный целиком (в том числе старые тесты).

Уже есть: `css/tokens.css`, `css/app.css`, `css/admin.css` (сняты с макетов),
`assets/logo.svg`, `mockups/*`, `tools/check-fs-access.html`.
Кода приложения, данных и тестов ещё нет.

## 0. Каркас и данные — ✅ готово

**Что делаем**
- `tests.html`: подключает `workshops/*.js`, `js/core/*` и тесты из `tests/*.test.js`;
  помощник `tests/runner.js` (`MKB.test`, `MKB.eq`, `MKB.ok`) печатает в страницу
  зелёные и красные строки и итог.
- `workshops/mk3.js`: МК-3 из примера в `CLAUDE.md`, этап «Лента белым цветом»
  целиком (4 фрагмента, шаги по одному на блок). Остальные этапы — по мере
  появления кода от автора.
- Пустые файлы-заготовки `js/core/*.js` с namespace.

**DoD**
- `tests.html` открывается и показывает итог без ошибок (первый тест — данные МК-3).
- `mk3.js` подключается через `<script src>` и кладёт объект в `MKB.workshops`.

## 1. `core/split.js` — дерево из отступов

**Что делаем**
- Табы → пробелы, пустые строки отбрасываются.
- Удаление комментариев `//` и `#` вне кавычек.
- Шаг отступа — по первому ненулевому отступу в этапе (2 или 4); `depth = отступ / шаг`.
- Хвост — строка по `/^[)\]}\s;,]+$/`, пишется в `closer` открывающего блока, в
  массив блоков не попадает.
- Открывающий блок — под ним строки большей глубины; `bodyCount` = число строк
  тела верхнего уровня; `parentId`.
- `position`, `group`, `free`, `text` без отступа.
- `norm` и `fields` — пока заглушкой, заполняется в этапе 2 (через `fields.js`).

**DoD** — тесты из таблицы `CLAUDE.md`:
- Arduino и Python одинаковой структуры → одно и то же дерево.
- `}` и `});` → хвосты, в блоки не попали.
- `} else {` и `elif x:` → обычные открывающие блоки, без спецветок в коде.
- Цикл в цикле → `depth: 2`, верный `parentId`.
- Шаг 2 и 4 → одинаковый `depth`; табы → верный `depth`.
- `//` и `#` в конце строки удалены, `//` внутри кавычек сохранён.
- Этап МК-3 разбирается в 11 блоков с правильными `bodyCount` и `closer`.

## 2. `core/fields.js`, `core/validate.js`, `core/serialize.js`

**Что делаем**
- `fields.js`: разбор `{{a|b|c}}` → `fields` (первое — ответ, `options`),
  `norm` с маркерами `<F0>`; проверка значения: обрезка краёв, схлопывание
  пробелов, регистр учитывается → `ok | wrong | case | empty`; ширина поля
  (длина эталона + 2).
- `validate.js`: `MKB.validate(assembled, blocks, values)` по восьми правилам
  (группа + мультимножество `norm`, `free`, взаимозаменяемые одинаковые
  строки, все ошибки сразу, хвосты не участвуют, поля отдельно, `ok` только
  когда всё `ok`). Статус `near` подключается в этапе 3.
- `serialize.js`: `MKB.buildCode(...)` — отступ по `depth` и шагу этапа,
  введённые значения вместо полей, хвосты на местах, пустая строка между
  фрагментами. Здесь же текст файла мастер-класса (`workshopToJs`) для админки.

**DoD**
- Тесты: точное совпадение → `ok: true`; перестановка внутри `free` → `ok`;
  перестановка между фрагментами → два `wrong`; две `FastLED.show();` в разных
  фрагментах → `ok`; пустые слоты → `empty`.
- Поля: верное → `ok`, другой регистр → `case`, лишние пробелы → `ok`, пусто → `empty`.
- Блок с незаполненным полем находит своё место (сравнение по шаблону).
- `buildCode` на МК-3 даёт ровно `FINAL` из `mockups/03-student.html`.
- `workshopToJs` → текст, который после `eval` даёт тот же объект (круговой тест).

## 3. `core/similarity.js` — близнецы

**Что делаем**
- Левенштейн, нормализованное сходство, порог 0.8.
- `MKB.findSimilar(blocks)` → `{ pairs, diffs }`; `diffs` — спаны по общему
  префиксу и суффиксу.
- Подключить `near` в `validate`.

**DoD**
- `leds[0] = CRGB::Red;` / `leds[1] = CRGB::Red;` → пара, спаны указывают на `0` и `1`.
- Непохожие строки МК-3 пар не образуют.
- Близнецы переставлены → два `near`, не `wrong`.

## 4. `index.html` и вёрстка по макетам

**Что делаем**
- `index.html`: подключения в обязательном порядке
  `workshops/*.js → core/* → state.js → ui/* → admin/* → app.js`, SVG-спрайт
  иконок из макетов, контейнер экранов.
- Статичная вёрстка трёх экранов на реальных данных МК-3 (без логики): стартовый,
  ученик, админка. Сверить `css/*.css` с `mockups/*.css`, дописать недостающее.
- Проверить конфликты классов между `app.css` и `admin.css` (например, `.main`
  в `admin.css` не ограничен экраном и задевает стартовый).

**DoD**
- В окне 1280×720 каждый экран совпадает с макетом: размеры, порядок, тексты.
- Страница целиком не прокручивается; прокручиваются только список МК, две
  колонки ученика, центр админки. Шапка и «Проверить» на месте.
- `#include <FastLED.h>` и `addLeds<WS2812, …>` выводятся как текст, не как теги.
- Номеров строк нигде нет.

## 5. `state.js` и `ui/render.js` — дерево слотов

**Что делаем**
- `state.js`: дерево слотов в памяти (без хранилищ): изначально слоты верхнего
  уровня; поставить / снять / переставить блок; при установке открывающего —
  `bodyCount` пустых слотов + хвост; при снятии — содержимое рекурсивно в
  палитру; обход в глубину → `assembled`; значения полей; палитра, перемешанная
  Фишером–Йетсом с проверкой несовпадения с эталоном; счётчик «осталось блоков».
- `render.js`: рекурсивная отрисовка слотов, пазлы по образцу `shape()`,
  «С» с хвостом-замком, отступ по глубине, полоска типа, кружок фрагмента,
  `<mark>` у близнецов (текст экранируется до вставки тегов), поля ввода
  (список / свободный ввод, ширина по эталону).

**DoD**
- На старте видны 6 пустых слотов верхнего уровня МК-3.
- Поставили `void loop() {` (временно из консоли / отладочно) → появились 2
  слота и хвост; сняли → слоты и хвост исчезли, содержимое вернулось в палитру.
- Вложенный открывающий блок раскрывается так же, рекурсивно.
- Все восемь состояний блока из артборда 3и различимы, в том числе в оттенках серого.

## 6. Взаимодействие ученика

**Что делаем**
- `ui/drag.js`: pointer events; блок поднят, наклонён, с тенью; синий пунктир
  у слота под курсором; вне слота — возврат; обратно в палитру — снять;
  перестановка внутри уровня.
- Клавиатура: Tab по блокам, Enter — в первый свободный слот / вернуть, ↑↓ —
  переставить; видимый фокус.
- Поля: выпадающий список (опции перемешаны) и свободный ввод.
- «Проверить»: активна при всех заполненных слотах; статусы всех слотов и полей
  сразу; строка шага меняется на «Почти получилось…» / «Всё верно!».
- Подсказка: один следующий нужный блок в палитре, зелёное свечение, гаснет при
  установке или через 30 с; при заполненных слотах кнопка неактивна и светится
  «Проверить».
- Строка шага: «Шаг N из M» + описание следующей строки — первой в эталонном
  порядке непоставленной (по `norm`); подсказка подсвечивает тот же блок.
- `ui/modal.js`: общая модалка; модалка успеха с кодом, «Скопировать код»
  (`navigator.clipboard` → фолбэк на `textarea` + `execCommand('copy')`), «Закрыть».

**DoD**
- Этап МК-3 собирается мышью и тачпадом полностью; и так же с клавиатуры.
- Ошибки подсвечиваются все сразу, поле с неверным значением — отдельно от
  порядка, регистр → «проверь заглавные».
- Подсказка ведёт по шагам до конца и гаснет по таймеру.
- Скопированный код вставляется в текстовый редактор и совпадает с `buildCode`
  (с введёнными значениями).
- Прокрутка колонок не ломает перетаскивание (автопрокрутка у края колонки).

## 7. Стартовый экран и навигация

**Что делаем**
- `app.js`: роутинг между экранами (без хранения состояния ученика).
- Стартовый экран: сетка карточек из `MKB.workshops`, бейдж языка.
- Модалка пароля: пароль открытым текстом в коде, показ/скрытие, ошибка текстом
  со значком.
- Экран ученика: выпадающий список этапов; смена этапа, «В начало», логотип —
  с подтверждением, если что-то поставлено, иначе сразу.

**DoD**
- Все переходы и модалки соответствуют артбордам 1б, 1в, 3б, 3ж, 3з, 3и.
- После перезагрузки страницы сборки нет (ничего не запоминается).
- Список из 12+ МК прокручивается, шапка стоит.

## 8. Админка

**Что делаем**
- `admin/save.js`: `showDirectoryPicker`, хэндл папки в IndexedDB,
  `queryPermission`/`requestPermission`, состояние «Подключить папку»; запись
  `workshops/<id>.js`; для нового МК — дописать `<script src>` в `index.html`
  (в группу workshops); удаление МК; запасной путь — скачивание `Blob`.
  Все обращения к хранилищам в try/catch.
- `admin/editor.js`: сайдбар (список, сворачивание, «+ Мастер-класс», корзина с
  модалкой); поля «Название», «Язык»; этапы: кнопки, «+ Этап», «Название этапа»,
  «Удалить этап» (неактивна у единственного); фрагменты: код текстом, `free`,
  ↑↓, удаление с модалкой, свёрнутая карточка с превью и счётчиком, «+ Фрагмент».
- «Выровнять отступы»: табы → пробелы, отступы к шагу, раскладка по глубине.
- `admin/steps.js`: режим «Шаги» — строки со «Шаг N», отступом, пометкой
  фрагмента, полем описания, предупреждением у пустых; «← К фрагментам»;
  перенос описаний по `line` (одинаковые строки — k-е вхождение к k-му) с
  модалкой при изменённом коде.
- Статус «Есть несохранённые изменения» / «Сохранено»; «Посмотреть как ученик»
  только после сохранения.

**DoD**
- Все артборды 2–2к воспроизводятся.
- Создали МК → сохранили → перезагрузили страницу → МК в списке, файл и строка
  в `index.html` на месте, прочие файлы не тронуты.
- Правка существующего МК перезаписывает только его файл; `git diff` чистый,
  кроме изменённого.
- Без выбранной папки «Сохранить» и «Посмотреть как ученик» неактивны.
- Нет проверок качества кода и экспорта.

## 9. Прогон целиком

**Что делаем**
- Создать этап в админке, сохранить, пройти как ученик, скопировать код в
  Arduino IDE, скомпилировать и прошить; то же для Python-этапа в PyCharm.
- Смена учеников: пройти этап, вернуться к списку, открыть снова — всё с нуля.

**DoD**
- Код компилируется и работает на ленте.
- Проверка всех экранов в 1280×720 (масштаб 150% на 1920×1080).
- Найденные расхождения с макетами исправлены или записаны как задачи.

## Решённые вопросы

1. **Одинаковые строки.** В этапе их быть не должно. Если есть — у ученика
   взаимозаменяемы (обе версии засчитываются); при переносе описаний k-е
   вхождение получает описание k-го вхождения.
2. **Описание шага** — описание следующей строки: программа собирается сверху
   вниз, следующая — первая в эталонном порядке непоставленная строка
   (по `norm`), в том числе в свободном фрагменте. Подсказка указывает на тот же блок.
