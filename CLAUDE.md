# Конструктор кода по блокам

Учебное приложение для мастер-классов по программированию и электронике.
Ученик собирает программу из перемешанных строк-блоков, при необходимости
вписывает значения в поля, проверяет себя и копирует готовый код в Arduino IDE
или PyCharm.

Аудитория — школьники, в том числе младшие. Занятие идёт в классе без интернета,
за одним компьютером в течение дня сменяется несколько учеников.

Рабочий экран — ноутбук, мышь или тачпад, не мобильное: 1920×1080 при масштабе
150%, то есть **1280×720 CSS-пикселей**. Вёрстка проверяется в этом размере.

## Жёсткие ограничения

Нарушение любого из них ломает продукт целиком.

- **Никакой сборки.** Нет npm, нет package.json, нет node_modules, нет бандлера.
- **Никаких зависимостей.** Ни CDN, ни вендоринга библиотек. Только ванильный JS.
- **Работает по `file://`.** Файл открывается двойным кликом из папки.
  Следствия:
  - `<script type="module">` — **запрещено**, блокируется CORS. Только обычные
    `<script src>`, порядок подключения важен.
  - `import` / `export` запрещены. Модули общаются через глобальный namespace
    `window.MKB`.
  - `fetch()` не работает. Список мастер-классов нельзя получить сканированием
    папки — каждый файл подключается строкой `<script src>` в `index.html`
    вручную.
  - `navigator.clipboard` может не сработать. Нужен фолбэк на скрытую
    `<textarea>` + `document.execCommand('copy')`.
  - Запись файлов из админки — File System Access API (`showDirectoryPicker`,
    Chrome/Edge): проверено на целевом ноутбуке через `tools/check-fs-access.html`,
    работает по `file://`. Скачивание через `Blob` + `a.download` остаётся запасным путём.
- **Целевой браузер** — Chrome / Edge актуальных версий. ES2020 можно.

Откуда брать вид экранов и на что ориентироваться.

| Что | Где |
|---|---|
| Макеты трёх экранов и всех их состояний | `mockups/01-start.html`, `02-admin.html`, `03-student.html` — открываются двойным кликом |
| Токены: цвета, отступы, радиусы, шрифт, тени | `css/tokens.css` — единственный источник значений |
| Стили, снятые с макетов | `css/app.css` (общее, стартовый экран, ученик), `css/admin.css` |
| Логотип | `assets/logo.svg`; клик по нему возвращает к списку мастер-классов |
| Откуда взят стиль | дизайн-система FS-LMS 2.0: `DesDoc/ui-kit/variables.scss`, `DesDoc/Mockups/_shared.css` (open-color, системный шрифт, шкала размеров 12/14/16/22/26) |

Правила:

- **Макет — это вид, а не код.** Скрипты в `mockups/*.html` только собирают
  картинку для показа. Размеры, порядок элементов, тексты и состояния берутся
  из макета один в один; функция `shape()` в `03-student.html` — образец
  рисования пазла. Макет расходится с этим файлом — остановиться и спросить,
  трактовку не выбирать.
- **Главный размер — 1280×720.** Страница целиком не прокручивается:
  прокручиваются внутренние области (список мастер-классов, две колонки ученика,
  центр админки). Шапка и «Проверить» стоят на месте.
- **Только переменные из `css/tokens.css`.** Новые цвета, размеры и тени не
  изобретать; нужно значение, которого нет — сначала предложить.
- `mockups/_v1-site-style/` — устаревший вариант в стиле сайта. Не использовать.
- **Номера строк не показывать нигде.**
- Статус блока **никогда не передаётся только цветом**: контур, значок, подпись
  (образец состояний — артборд 3и в `03-student.html`).

Цветовая семантика блоков:

| Признак | Что означает |
|---|---|
| полоска слева: синяя / фиолетовая / оранжевая | обычная строка / открывающая (блок в форме буквы «С») / строка с полем ввода |
| цветной кружок у строки | номер фрагмента (жёлтый, розовый, голубой, тёмно-серый, дальше по кругу) |
| зелёный контур со свечением, уходящим в размытие | подсказка. **В палитре справа зелёного больше нет.** Тем же свечением светится «Проверить», когда подсказывать нечего |
| зелёный сплошной контур, ✓, «верно» | после проверки |
| оранжевый пунктир, ≈, «почти» | почти верный |
| красная штриховка, ✕, «не здесь» | неверный |
| серая плашка с замком внутри «С» | хвост |

Вид — в макетах (`mockups/`), здесь только суть.

внизу «+ Мастер-класс», у строки корзина с модалкой-предупреждением.

## Хранение

Приложение **ничего не помнит об ученике**: каждый следующий начинает с нуля.
Ни прогресса, ни отметок «этап пройден», ни `sessionStorage` для сборки нет —
сборка живёт только в памяти вкладки. Черновика в админке тоже нет.

| Что | Где | Роль |
|---|---|---|
| Готовые мастер-классы | `workshops/*.js`, подключены в `index.html` | источник истины, лежит в репозитории |
| Сохранение из админки | прямая запись в `workshops/*.js` через File System Access API | кнопка «Сохранить»; экспорта нет |

Админка редактирует мастер-классы, уже загруженные через `<script src>`, прямо
из памяти; «Сохранить» переписывает файл. Папку проекта пользователь выбирает
через системный диалог (выбирать саму папку проекта: «Рабочий стол», «Документы»,
«Загрузки» браузер не разрешает). Новый мастер-класс: приложение дописывает
`<script src>` в `index.html` той же записью.

Выбранная папка запоминается в IndexedDB (это настройка админки, не данные ученика):
на целевом ноутбуке Chrome после перезагрузки страницы отдаёт разрешение сразу
(`queryPermission` → `granted`), повторный выбор папки не нужен. Всё равно
предусмотреть запасное состояние: если разрешения нет (`prompt`) или папка
не запомнена — при входе в админку показать «Подключить папку» (один клик или
выбор папки), а «Сохранить» и «Посмотреть как ученик» до этого держать неактивными. Импорта нет. Любое обращение к
хранилищам браузера оборачивать в try/catch.

## Структура программы: два правила

Ключевое решение проекта. Разборщик **не знает языков**. Вложенность берётся из
отступов исходного кода, и этого достаточно и для Arduino, и для Python.

**Правило 1. Глубина = отступ / шаг.** Шаг определяется автоматически по первому
ненулевому отступу в этапе (2 или 4).

**Правило 2. Строка только из закрывающей пунктуации — это хвост.**
Регулярка `/^[)\]}\s;,]+$/`. Хвост привязывается к своему открывающему блоку, в
палитру не попадает, в проверке не участвует, переставить его нельзя.

**Открывающий блок** — любая строка, под которой идут строки большей глубины.
Ни `{`, ни `:` при этом не разбираются.

| Arduino | Python |
|---|---|
| `void loop() {` — открывающий, тело 2 строки | `for i in range(10):` — открывающий, тело 2 строки |
| `  fill_solid(…);` — глубина 1 | `    print(i)` — глубина 1 |
| `}` — хвост | правило 2 не срабатывает, хвоста нет |

`} else {` и `elif x:` работают сами собой: обе строки не являются чистой
пунктуацией, значит обычные блоки; под обеими идут строки глубже, значит
открывающие; предыдущее тело закрывается тем, что глубина вернулась к
родительской. Отдельных веток для них не писать.

Поле `language` после этого влияет **только на подсветку синтаксиса**.

## Рабочая область как дерево

Как это выглядит — `mockups/03-student.html`: блоки-пазлы, открывающий блок в форме
буквы «С» с пустыми слотами внутри и серым хвостом-перекладиной.

Изначально показываются слоты только **верхнего уровня**. Структура открывается
по мере сборки, а не выдаётся вперёд.

```
[                          ]   ← #define LED_PIN 5
[                          ]   ← #define NUM_LEDS 30
[                          ]   ← #include <FastLED.h>
[                          ]   ← CRGB leds[NUM_LEDS];
[                          ]   ← void setup() {
[                          ]   ← void loop() {
```

Ученик ставит открывающий блок — под ним разворачиваются пустые слоты его тела
и хвост:

```
[ void loop() {            ]        [ for i in range(10):     ]
   [                       ]           [                      ]
   [                       ]           [                      ]
│  }
```

| Ситуация | Поведение |
|---|---|
| Поставлен открывающий блок | появляются слоты по числу строк его тела **верхнего уровня** + хвост, если есть |
| Вложенный блок внутри тела | раскрывается так же, рекурсивно |
| Открывающий блок убран | его содержимое возвращается в палитру, слоты и хвост исчезают |
| Хвост | серый, не берётся, не переставляется, в проверке не участвует |
| Пустой слот в середине | допустим, при проверке получает статус `empty` |
| Отступ слота | рисуется по глубине, не берётся из текста блока |

Над палитрой — счётчик «осталось блоков: N». Без него ученик не понимает, всё ли
разложено, когда видимые слоты кончились.

## Модель данных

Мастер-класс состоит из **этапов**. Этап — самостоятельный код («бегущий
огонёк», «плавная радуга»); между собой этапы не связаны.

```js
window.MKB = window.MKB || {};
window.MKB.workshops = window.MKB.workshops || [];
window.MKB.workshops.push({
  id: "mk3",
  title: "МК-3: Адресная лента WS2812",
  language: "arduino",          // "arduino" | "python" — бейдж на карточке и подсветка
  stages: [
    {
      id: "white",
      title: "Лента белым цветом",
      fragments: [
        {
          free: true,           // строки верхнего уровня взаимозаменяемы
          code:
`#define LED_PIN 5
#define NUM_LEDS 30
#define POT A0
#include <FastLED.h>`
        },
        { free: false, code: "CRGB leds[NUM_LEDS];" },
        {
          free: false,
          code:
`void setup() {
  FastLED.addLeds<WS2812, LED_PIN, GRB>(leds, NUM_LEDS);
  FastLED.setBrightness(200);
}`
        },
        {
          free: false,
          code:
`void loop() {
  fill_solid(leds, NUM_LEDS, CRGB::{{White|Red|Blue}});
  FastLED.show();
}`
        }
      ],
      steps: [                  // по одному на блок, в порядке блоков; хвосты шагов не имеют
        { line: "#define LED_PIN 5", text: "Задайте пин, к которому подключена лента." },
        { line: "#define NUM_LEDS 30", text: "Укажите, сколько светодиодов на ленте." }
        // …
      ]
    }
  ]
});
```

**Шаг** — описание одной строки-блока. Ученик видит описание следующего блока
под шапкой. Поле `line` — текст строки без отступа: по нему описания
переносятся при повторной разборке фрагментов (см. «Поведение админки»). Строка
без описания допустима: `text` пустой.

**Фрагмент** — авторская единица, не то, что таскает ученик. Порядок фрагментов
между собой зафиксирован всегда. Единственный переключатель — `free`: строки
фрагмента **верхнего уровня** взаимозаменяемы между собой. Тела вложенных блоков
`free` не затрагивает.

Границы фрагментов задают пустые строки в итоговом коде при копировании.

Комментарии в коде **удаляются при разборе** — их место в описаниях шагов.
Удалять `//` и `#` только вне кавычек: `Serial.println("http://…")` ломать
нельзя.

Никаких режимов, уровней и дистракторов в модели нет. Сложность этапа
регулируется только количеством и размером полей ввода.

## Поля ввода

Разметка прямо в коде фрагмента:

```
CRGB::{{White}}                                свободный ввод
CRGB::{{White|Red|Blue}}                       выпадающий список
fill_solid{{(leds, NUM_LEDS, CRGB::White)}};   свободный ввод длинного куска
```

Первое значение — правильное. Остальные показываются в списке и перемешиваются.

| Правило | Решение |
|---|---|
| Регистр | **учитывается** — `crgb::white` не скомпилируется в Arduino IDE |
| Ошибка только в регистре | отдельный статус «проверь заглавные буквы», не глухая ошибка |
| Пробелы внутри | схлопываются: `(leds,NUM_LEDS)` = `(leds, NUM_LEDS)` |
| Пробелы по краям | обрезаются |
| Пустое поле | статус `empty`, не `wrong` |
| Ширина поля | по длине эталона + 2 символа, не больше — иначе поле выдаёт длину ответа |
| Копирование | подставляются **введённые** значения, не эталонные |
| Момент проверки | вместе с порядком, по одной кнопке «Проверить» |

Блок с полем в проверке порядка сравнивается **по шаблону**, а не по введённому
тексту: `norm` содержит маркер поля. Иначе блок с незаполненным полем не найдёт
своё место.

## Ядро: контракты

### `MKB.splitFragments(fragments)` → `Block[]`

Плоский массив в порядке исходных строк; дерево выражено через `depth` и
`parentId`.

```js
Block = {
  id: "b6",
  text: "fill_solid(leds, NUM_LEDS, CRGB::{{White|Red|Blue}});",  // без отступа
  norm: "fill_solid(leds, NUM_LEDS, CRGB::<F0>);",
  depth: 1,
  parentId: "b5",        // открывающий блок, null на верхнем уровне
  position: 6,           // эталонная позиция в плоском обходе
  group: 4,              // номер фрагмента
  free: false,
  bodyCount: 0,          // сколько слотов раскрыть под этим блоком
  closer: null,          // "}" у открывающего, если хвост был; иначе null
  fields: [{ id: "F0", answer: "White", options: ["White","Red","Blue"] }]
}
```

Табы разворачиваются в пробелы до подсчёта отступа. Пустые строки отбрасываются.
Отступ в `text` не хранится — он выводится из `depth` при отрисовке и при сборке
итогового кода.

### `MKB.findSimilar(blocks)` → `{ pairs, diffs }`

Пары почти одинаковых строк — главный источник ошибок на уроке
(`setPixelColor(0, …)` против `setPixelColor(1, …)`). Нормализованное расстояние
Левенштейна, порог 0.8. `diffs` — спаны различающихся символов, считаются общим
префиксом и суффиксом. Спаны оборачиваются в `<mark>` во всех блоках пары, и в
палитре, и в слотах: ученик должен видеть, чем строки отличаются.

### `MKB.validate(assembled, blocks, values)` → `Result`

`assembled` — дерево слотов, развёрнутое обходом в глубину в плоский массив
`id`. Порядок при этом совпадает с порядком исходных строк, поэтому проверка
ничего не знает о дереве.

```js
Result = {
  ok: false,
  slots: [
    { index: 0, status: "ok" },
    { index: 1, status: "near" },      // близнец правильной строки
    { index: 2, status: "wrong" },
    { index: 3, status: "empty" }
  ],
  fields: [
    { id: "F0", status: "case" }       // ok | wrong | case | empty
  ]
}
```

Правила:

1. Блок на позиции `i` верен, если его `group` совпадает с группой эталонного
   блока на этой позиции **и** его `norm` входит в неизрасходованное
   мультимножество норм этой группы.
2. Внутри фрагмента с `free: true` порядок строк верхнего уровня любой.
3. Сравнение по `norm`, не по `id`. Две одинаковых строки `FastLED.show();` в
   разных фрагментах взаимозаменяемы — это не ошибка.
4. Неверный блок получает `near`, если он в паре с эталонным по `findSimilar`,
   иначе `wrong`.
5. **Подсвечиваются все неверные слоты, а не первый.** Аудитория младше, чем в
   типичном Parsons-задании; поиск единственной ошибки за раз фрустрирует.
6. Хвосты в проверке не участвуют вовсе — они не могут быть неправильными.
7. Поля проверяются независимо от порядка: блок может стоять верно, а значение
   быть неверным.
8. `ok: true` только когда все слоты заполнены, все `ok`, и все поля `ok`.

### `MKB.buildCode(assembled, blocks, values)` → `string`

Собирает итоговый код: отступ по `depth`, введённые учеником значения вместо
полей, хвосты на своих местах, пустая строка на границе фрагментов. Это то, что
копируется в буфер.

## Поведение интерфейса ученика

Вид и все состояния — `mockups/03-student.html`.

Палитра перемешивается целиком (Фишер–Йетс) с проверкой, что результат не
совпал с эталоном.

**Установка блока — перетаскиванием.** Блок «подтягивается» за курсором:
приподнят, чуть наклонён, с тенью; слот под ним подсвечивается синим пунктиром.
Отпустить вне слота — блок возвращается. Вернуть блок — перетащить обратно в
палитру. Переставить внутри уровня — тоже перетаскиванием. Реализация на
pointer events (мышь и тачпад). Клика-установки нет.

**Подсказка.** Кнопка с лампочкой в шапке. Зелёным контуром и свечением,
уходящим в размытие, подсвечивается **один** следующий нужный блок в палитре.
Без текста, слот не подсвечивается, поля не заполняются, эталон не показывается.
Гаснет, когда блок поставили, или сама через 30 секунд после нажатия; после
этого кнопку можно нажать снова. Если подсказывать нечего (все слоты заполнены)
— кнопка неактивна, а тем же свечением подсвечивается «Проверить», чтобы её
находили.

**Описание шага** — под шапкой по центру, без плашки: «Шаг N из M» и описание
следующей строки. Считаем, что программа собирается сверху вниз: следующая —
первая в эталонном порядке строка, которая ещё не поставлена (сравнение по `norm`;
в свободном фрагменте — так же, по эталонному порядку). N — её номер в эталоне.
Подсказка подсвечивает этот же блок.

**Этапы.** Выпадающий список в шапке, переход свободный, отметок «пройден» нет. Если сборка не в начальном
состоянии (поставлен хотя бы один блок), смена этапа — через модалку
с подтверждением: сборка при переходе сбрасывается. В начальном состоянии переход
без вопросов.

**«В начало»** очищает сборку после подтверждения. **Логотип** возвращает к
списку мастер-классов, тоже с подтверждением, если что-то уже поставлено.

**«Проверить»** активна только когда заполнены все слоты. Подсвечиваются все
ошибки сразу, а не первая. При успехе — модалка с галочкой и кодом, кнопки
«Скопировать код» и «Закрыть» (кнопки «Следующий этап» нет).

Состояния блока, все должны быть видимо различимы (цвета и признаки — в разделе
«Дизайн»): `в палитре` · `в слоте` · `верный` · `почти верный` · `неверный` ·
`подсвечен подсказкой` · `слот пустой` · `хвост`. Временное состояние — блок,
который несут.

Клавиатура (на случай, когда мышь недоступна): Tab по блокам, Enter — поставить в
первый свободный слот или вернуть, стрелки ↑↓ — переставить. Видимый фокус
обязателен.

На 720 px по высоте колонки прокручиваются независимо; шапка, строка шага и
«Проверить» остаются на месте.

## Поведение админки

Вид — `mockups/02-admin.html`.

Структура редактора: мастер-класс (название, язык) → **этапы** → в этапе два режима,
переключаются кнопками.

- **Этапы.** Ряд кнопок-этапов с номером и «+ Этап» (новый этап встаёт в конец и
  выбирается, название и фрагмент пустые), под ним поле «Название этапа» и «Удалить
  этап» (модалка с предупреждением, что пропадёт; у единственного этапа кнопка
  неактивна). Переупорядочивания этапов нет.

- **«Фрагменты».** Карточки-фрагменты: многострочное поле с кодом, переключатель
  «Строки можно менять местами» (`free`), стрелки ↑↓, удаление (модалка),
  «Выровнять отступы», свёрнутая карточка — превью первой строки и счётчик.
  Внизу «+ Фрагмент» и закреплённая панель с кнопкой «Разобрать на шаги →».
- **«Шаги».** Фрагменты заменяются списком строк-блоков (код разобран). У каждой
  строки метка «Шаг N», отступ по глубине, пометка фрагмента и поле описания.
  Строка без описания подсвечивается предупреждением (запрета нет). Кнопка
  «← К фрагментам» возвращает к правке кода; описания при этом не пропадают.

Код фрагмента правится **как текст целиком**; блоки перегенерируются при
разборке. Не редактировать отдельные блоки.

**Повторная разборка.** Если описания уже есть, а код изменился, перед разборкой
модалка: описания сохранятся у неизменившихся строк (по совпадению `line`),
у изменённых и удалённых пропадут, новые строки будут без описания.
Одинаковых строк в этапе быть не должно; если они всё же есть, k-е вхождение
строки получает описание k-го вхождения в старых шагах. У ученика одинаковые
строки взаимозаменяемы (правило 3 проверки). Если код не
менялся, шаги открываются сразу.

**Новый мастер-класс** — пустые название и язык и один пустой фрагмент;
«Разобрать на шаги» неактивна, пока нет кода.

**«Сохранить»** пишет файл мастер-класса. В шапке статус: «Есть несохранённые
изменения» / «Сохранено». **«Посмотреть как ученик»** доступна только когда всё
сохранено и открывает экран ученика с этим мастер-классом. Экспорта нет.

**Удаление** мастер-класса (корзина в сайдбаре) и фрагмента — через модалку с
предупреждением, что именно пропадёт.

**Проверок кода при сохранении нет:** автор вставляет рабочий код, задача
программы — помочь его собрать. Предупреждений про отступы, длину строк и т. п.
не делать.

Отступ остаётся несущей конструкцией (см. «Структура программы»): «Выровнять
отступы» убирает табы, приводит отступы к шагу и раскладывает по глубине. Нужна
постоянно — код вставляется откуда попало.

## Стиль кода

- Ванильный ES2020, обычные функции, без классов ради классов.
- Имена и комментарии по-русски, код по-английски.
- Никакого `innerHTML` с данными мастер-класса без экранирования: код содержит
  `<`, `>` и `&` (`#include <FastLED.h>`, `FastLED.addLeds<WS2812, …>`). Только
  `textContent` или явная `escapeHtml`. Исключение — вставка `<mark>` и полей
  ввода, но текст экранируется до вставки тегов.
- CSS: только переменные из `css/tokens.css`, никаких хардкод-цветов и
  произвольных размеров (раздел «Дизайн»). Классы и разметку брать из
  `css/*.css` и макетов, не переименовывать без причины.
- Файл больше 250 строк — повод разделить.

## Тесты

`tests.html` подключает `workshops/*.js`, `js/core/*`, `tests/runner.js` и
`tests/*.test.js` и печатает результат в страницу.
Открывается двойным кликом. Никакого раннера.

| Кейс | Ожидание |
|---|---|
| Arduino и Python с одинаковой структурой | одно и то же дерево из одного разборщика |
| `}` отдельной строкой | хвост, в палитру не попал |
| `});` от `addLeds` | хвост |
| `} else {` | обычный блок, открывающий |
| `elif x:` | обычный блок, открывающий |

| Перестановка между фрагментами | два `wrong` |

## Чего в этой версии нет

Не добавлять без отдельной просьбы:

- сборку, npm, TypeScript, React, любые библиотеки;
- бэкенд, API, базу, аккаунты, синхронизацию;
- импорт файла мастер-класса — редактируются загруженные через `<script src>`;
- экспорт скачиванием как основной путь (только как запасной), скачивание `.ino`
  и `.py` — только копирование в буфер;
- **память об ученике:** прогресс, отметки «пройден», `sessionStorage` для сборки;
- установку блока кликом (основной способ — перетаскивание; клавиатура — запасной);
- всплывающие тексты подсказок: подсказка только подсвечивает блок;
- проверки и предупреждения о качестве кода в админке;
- страницу для печати — раздатку преподаватель готовит сам;
- дистракторы, лишние строки в палитре;
- режимы и уровни сложности как флаги — сложность задаётся полями ввода;
- разбор синтаксиса конкретного языка — структура только из отступов;
- ручную расстановку отступов учеником — глубина следует из дерева;
- блоки условий и циклов в стиле Scratch — блок это строка кода, пазл только вид;
- запуск кода, Pyodide, эмуляцию Arduino.
